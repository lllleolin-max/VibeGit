AI не только пишет код, но и выполняет действия: может очистить файлы, перезаписать текущий результат или откатить проект к неверной версии, вернув рабочий проект в состояние нескольких часов назад. Страшна не одна неверная строка кода, а ситуация, когда после одного действия весь проект вдруг словно исчезает.

VibeGit — это локальное хранилище версий вашего проекта. Сохраняйте важные этапы: даже если AI ошибочно очистит, перезапишет или откатит проект, вы увидите, что произошло, и безопасно вернётесь к подтверждённой версии.

VibeGit скрывает Git за понятными действиями: добавить проект, сохранить версию, просмотреть изменения, отложить работу, вернуться к старой версии и сделать резервную копию в GitHub. Не нужно сначала изучать commit, branch или reset.

> **Every AI change, saved and reversible.**
>
> VibeGit восстанавливает сохранённые версии. Сначала включите защиту версий и создайте точку сохранения; восстановление несохранённых изменений не гарантируется.

## Знакомая поздняя ночь

В десять вечера проект наконец работает. Вы просите AI «навести порядок и вернуться к стабильной версии», но он ошибается: очищает текущие файлы или откатывает проект к очень старой версии.

Проект вдруг становится неузнаваемым: только что готовая страница исчезла, исправленная проблема вернулась, и непонятно, с чего начинать восстановление.

VibeGit сохраняет не смутное воспоминание, а подтверждённые вами версии проекта. Как хранилище, он оставляет важные точки сохранения локально: вы проверяете изменения и влияние, а затем безопасно возвращаете проект к нужной версии.

## Возможности

| Что нужно | Как помогает VibeGit |
| --- | --- |
| AI очистил, перезаписал или неверно откатил проект | Хранит важные версии в изолированных точках сохранения: проверьте, что произошло, и безопасно восстановите подтверждённую версию. |
| Сбой компьютера, новый компьютер или очищенный локальный проект | После одного подключения GitHub синхронизируйте версию в выделенный Private-репозиторий одним действием. Восстанавливаемые версии останутся и локально, и в облаке без изменения существующего `origin`. |
| Вернуться из неудачной версии | Сначала создаёт страховую точку и показывает влияние; после восстановления его можно отменить. |
| Отложить незавершённую работу | Безопасно убирает текущие изменения и точно возвращает их при необходимости. |
| Работать без знания Git | Использует обычные слова: проект, точка сохранения, вернуться к этой версии. |
| Записывать работу Agent | Единый Agent Events CLI создаёт точки защиты до и после задач; включены шаблоны Hook. |

## Для Vibe Coding

- **Понятно:** читаемые точки сохранения, описания задач и Diff вместо хешей коммитов.
- **Обратимо:** предварительный просмотр влияния, автоматическая страховка и отмена восстановления.
- **Ненавязчиво:** локальное сохранение и восстановление не зависят от сети, GitHub или Agent.
- **Защищённо:** проекты изолированы; перед удалённым бэкапом проверяется чувствительная информация, локальные файлы не удаляются.

## Синхронизация с приватным хранилищем GitHub

Локальные точки сохранения помогают вернуть проект после ошибочной очистки, перезаписи или отката AI. Приватный бэкап GitHub — это вторая страховка, чтобы важные версии не оставались только на одном компьютере.

Подключите GitHub один раз, а затем синхронизируйте любой важный этап с выделенным Private-репозиторием одним действием. При поломке компьютера, переходе на новое устройство или случайной очистке локальной папки проекта у вас останется независимая облачная копия.

VibeGit использует отдельный remote `vibegit`. Он никогда не перезаписывает, не заменяет и не изменяет существующий `origin`: обычный репозиторий для разработки остаётся прежним, а VibeGit добавляет приватный уровень защиты для важных версий.

После установки [GitHub CLI](https://cli.github.com/) откройте в проекте **GitHub Backup** и выберите создание SSH-ключа. VibeGit авторизуется через браузер, создаёт отдельный ключ Ed25519 в данных приложения и регистрирует в GitHub только открытый ключ. Подробнее: [настройка GitHub](docs/GITHUB_SETUP.md).

## Начало работы

### 1. Автоматическое развёртывание через Codex или Claude Code

В папке репозитория скопируйте и вставьте в Codex или Claude Code следующую инструкцию:

```text
Разверни VibeGit в текущем рабочем пространстве одним действием: проверь наличие Node.js 24+, pnpm 9+ и Git 2.23+; если всё доступно, выполни pnpm install, затем запусти pnpm dev. Если зависимость отсутствует, объясни это и сначала установи её. После завершения сообщи результат запуска и следующие шаги.
```

> Эта инструкция запускает VibeGit из исходного кода и предназначена для тех, кто уже скачал или клонировал репозиторий.

### 2. Скачать установщик Windows и развернуть VibeGit Skill

[**Скачать последний установщик Windows x64**](https://github.com/lllleolin-max/VibeGit/releases/latest)

Для установщика не нужны Node.js или pnpm. После установки VibeGit запускается из меню «Пуск»; удаление программы не удаляет данные VibeGit.

> **Установщик не устанавливает Skills из репозитория автоматически.** При использовании VibeGit через установщик Windows также разверните `vibegit-change-summary`. Он позволяет Codex или Claude Code после задачи записывать понятное описание изменений, которое VibeGit покажет в следующей точке сохранения.

<details>
<summary><strong>Скопировать в Codex или Claude Code: автоматически развернуть VibeGit Skill</strong></summary>

Skill будет развёрнут только для установленных на компьютере Agent; остальные Skills сохранятся:

```text
Разверни VibeGit Skill. VibeGit уже установлен через установщик Windows. Получи skills/vibegit-change-summary/ из https://github.com/lllleolin-max/VibeGit, сначала проверь SKILL.md, затем скопируй его (не перемещай и не удаляй исходник) в глобальный каталог Skills каждого установленного Agent: для Codex это %USERPROFILE%\.codex\skills\vibegit-change-summary\SKILL.md, для Claude Code — %USERPROFILE%\.claude\skills\vibegit-change-summary\SKILL.md. Настраивай только Agent, установленные на этом компьютере; создай отсутствующие каталоги; не перезаписывай и не удаляй другие Skills. После завершения проверь, что в каждом целевом SKILL.md есть YAML frontmatter, и сообщи, что было развернуто и требуется ли перезапуск Agent.
```

</details>

### 3. Запуск из исходного кода

Установите Node.js 24+, pnpm 9+ и Git 2.23+, затем выполните в корне репозитория:

```powershell
pnpm install
pnpm dev
```

При первом запуске выберите папку проекта и нажмите **Включить защиту версий**. Git инициализируется только при необходимости, создаётся начальная точка сохранения; существующие обычные ветки не создаются и не переключаются. В Windows можно дважды щёлкнуть [`启动 VibeGit.bat`](启动%20VibeGit.bat).

## Безопасность по умолчанию

Принцип VibeGit: **сначала защитить, потом действовать.**

- Точки сохранения пишутся в изолированный `refs/vibegit/checkpoints/*`, не меняя ветку, `HEAD` и реальную область индексации.
- Не выполняются `reset --hard`, `clean -fd`, force push, изменение глобальной конфигурации Git и удаление `.git`.
- До восстановления создаётся проверяемая страховая точка; конфликтующие неотслеживаемые и игнорируемые файлы переносятся в закрытую область восстановления Git, а не удаляются.
- Перед GitHub-бэкапом ищутся ключи, учётные данные, базы данных, каталоги зависимостей/сборки, указатели LFS и большие файлы. Риск блокирует загрузку, сохраняя локальные файлы.
- Desktop Renderer не имеет доступа к Node.js и файловой системе.

См. [дизайн безопасности](docs/SECURITY.md) и [архитектуру](docs/ARCHITECTURE.md).
