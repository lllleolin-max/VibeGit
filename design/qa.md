# Design QA

检查对象：构建后的真实 Electron 应用。2026-07-12 的 Playwright 运行在 1920 × 1227 视口生成 `test-results/vibegit-empty.png`、`vibegit-timeline.png`、`vibegit-diff.png`、`vibegit-desktop-e2e.png` 和 `vibegit-first-use-protected.png`。

## 结论

READY FOR MVP。复核构建后的截图与 2 条真实 Electron E2E 后，未发现阻塞使用的视觉或交互问题。

- 信息层级：项目名称、保护状态、主操作和时间线主线清楚；界面没有暴露 HEAD、stash、reset 等主要 Git 术语。
- 首次启动：单一主任务明确，解释了本地保存和不会上传/删除文件，三步预期可理解。
- 时间线：保存点类型、来源、文件数和增删统计可扫读；空白区域保留安全感，没有传统 Git 面板噪声。
- Diff：文件列表与行级增删区域分离；已过滤 Git 元数据，只呈现用户关心的内容；红/绿之外仍有 `+`/`−` 文本线索。
- 危险操作：回退按钮使用警示色，执行前有影响预览与显式确认；完成后提供撤销和恢复区入口。失败或中断的回退使用警示提示，并可从项目页重新打开恢复区。
- 反馈：成功 toast 位于底部，不遮挡标题或主操作；加载、空、成功、错误、未登录、未连接、无文件变化 Agent 任务和失败恢复区状态均有实现。
- 适配：最小窗口限制为 980 × 640，关键操作在测试视口内无截断。
- 截图复核：首次使用的单一主任务明确；项目时间线信息密度适中；Diff 抽屉的文件列表、红绿行和回退操作层级清晰；恢复后的 toast 未遮挡主要按钮。

## 已修问题

- toast 原先可能与顶部操作重叠，已移到底部安全区。
- diff 原先显示 `diff --git`、index 和 hunk 元数据，已过滤为实际文件内容行。
- 生产 Renderer URL 原先校验过宽，已收紧为主窗口主 frame 的精确本地入口；恶意环境变量由 E2E 验证不会替换页面。
- 失败恢复原先只能在当前成功 toast 中打开恢复区；现已增加项目级失败恢复区入口，并绑定当前回退 token 防止显示无关旧记录。

## 非阻塞后续

- 尚未覆盖 Windows 高对比度、屏幕阅读器逐控件朗读和 200% 缩放的人工验收；P1 应补专门可访问性测试。
- 超长时间线与超大 diff 已有数据截断/滚动边界，但 P1 可增加虚拟列表以优化极端项目性能。
