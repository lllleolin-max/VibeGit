# Product Spec

## 产品定位

VibeGit 是面向非程序员 Vibe Coder 的本地桌面版本保险箱。它把底层 Git 操作翻译为“项目、保存点、这次改了什么、暂时收起、回到这个版本、备份到 GitHub”，让 Codex、Claude Code 等 Agent 的每轮修改都有可理解、可恢复的安全边界。

核心承诺：**Every AI change, saved and reversible.**

用户不需要理解 commit、branch、HEAD、stash、reset、working tree 等概念；这些只存在于实现和诊断层。

## P0 用户闭环

1. 选择本地项目根目录；已有 Git 项目必须选择其最外层根目录，避免越界备份或回退。
2. 开启版本保护：普通文件夹初始化 Git，随后创建初始保存点；已有 Git 项目不改写普通提交历史。
3. Agent 任务开始创建“修改前保护点”，任务结束如有变化创建“功能保存点”；无变化任务也在项目界面明确显示。
4. 用户可以查看时间线、文件列表、逐行 Diff、增删统计、Agent 与任务文本。
5. 回到旧版本前展示影响预览，自动建立保险点，保留未跟踪文件，必要时移至 Git 私有恢复区；完成后可以撤销。
6. 用户可把未完成修改“暂时收起”，随后准确取回。
7. 用户点击“连接 GitHub 并创建 SSH 密钥”即可完成浏览器授权和专用 Ed25519 公钥注册；随后可创建或连接 Private GitHub 仓库，并在敏感扫描通过后备份。

## 关键产品规则

- 本地保存与恢复不依赖 GitHub、网络或 Agent 安装状态。
- `.gitignore` 中的文件不自动进入保存点；已被真实 Git 暂存的文件仍按当前工作区内容安全捕获，避免“先暂存、后忽略”造成丢失。
- `.env`、密钥、凭据、数据库、依赖目录、构建产物、LFS 指针和大文件会阻止远程备份；VibeGit 不删除它们。
- 恢复冲突文件保存在 `.git/vibegit/recovery/<restore-id>`（或 worktree 对应 Git 私有目录），而不是用户项目中的隐藏目录；项目内 `.vibegit` 是普通用户数据。
- 失败或进程中断的恢复会保留可打开的恢复区入口；没有恢复区的普通预览失效不会伪装为有文件可取回。
- GitHub 备份使用专用 `vibegit` remote，不修改用户已有 `origin`；远程只接收扫描后树的独立导出提交链。

## 非目标

本轮不做团队协作、PR/Issue/CI 管理、GitLab/Gitee/Bitbucket、云端编辑器、云端源码托管、多人权限、移动端、复杂 merge conflict 自动处理或 Git 教学系统。
