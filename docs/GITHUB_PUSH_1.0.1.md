# VibeGit 1.0.1：GitHub 私有备份与升级验收

记录日期：2026-09-16（Asia/Shanghai）。本版本已覆盖安装到验收机器的原安装目录，保留原项目记录。GitHub 功能定位仍是手动推送到私有仓库的 `vibegit-backup` 分支。

## 本轮完成

- **已有仓库统一使用应用密钥。** 支持输入 GitHub HTTPS、普通 SSH 和 SSH 443 地址；验证为 Private 后，统一使用 `ssh://git@ssh.github.com:443/...` 与 VibeGit 专用密钥。旧版保存的地址在推送时兼容处理，不再依赖用户另外配置的 Git HTTPS 凭据或默认 SSH 密钥。
- **浏览器授权有明确进度。** 界面显示一次性设备授权码，并提供固定的 `https://github.com/login/device` 入口。只提取授权码，不把 GitHub CLI 原始输出、任意 URL 或凭据传给界面；授权完成或失败后清除代码，允许重试。
- **可检查和修复已撤销的密钥。** 检查本地公私钥配对和 GitHub 端注册状态；已撤销的应用公钥可重新关联。密钥文件损坏或不匹配时停止操作并提示，不覆盖、删除原密钥。
- **推送保留安全检查。** 上传前保存保护点并扫描实际快照，扫描后再次核验仓库可见性、账户和密钥。只向验证过的地址非强制推送，避免把仅存在于本地旧保存点中的敏感历史带到远端；认证、扫描和上传失败均记录为失败。
- **大项目不再阻塞项目列表。** 启动先读取登记信息，工作区状态明确为“待检查”，仅后台检查选中项目。GitHub 连接状态与文件扫描独立加载；创建或连接远端成功后不再等待额外扫描。
- **异步状态不会覆盖新操作。** 延迟返回的工作区检查保留新远端和成功推送状态，不重新插入已移除项目；检查期间保存点变化时标记状态未知。成功操作与后续列表刷新失败分别提示，避免重复提交。
- **Windows Git 超时有界处理。** 超时或输出超限时按本次进程 PID 终止进程树，不影响其他进程。父进程已退出时不使用可能复用的旧 PID；无法确认清理完成时有限返回错误，不无限等待，也不声称所有进程已退出。

## 功能边界与未验证项

- 本轮没有执行真实 GitHub 浏览器授权、创建远程私有仓库或联网上传。模拟认证、实际子进程输出测试和本地 Git 推送回归不能替代 GitHub 端到端网络验收。
- 当前提供手动私有备份。没有自动定时同步、任意分支推送、PR/冲突处理或应用内云端下载恢复；`vibegit-backup` 的安全快照历史不等同于完整本地保存点数据库。
- “上次备份成功”表示之前那次上传成功，不保证后来编辑的文件已在 GitHub；新修改需要再次备份。
- Windows 符号链接跳过项及其他平台行为仍需在相应环境补验。敏感文件扫描按已实现规则拦截，不能保证识别所有可能的秘密。
